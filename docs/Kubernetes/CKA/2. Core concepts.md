# 2. Core Concepts

## Summarize Commands

Create   > kubectl create f deployment definition.yml
Get      > kubectl get deployments
update   > kubectl apply f deployment definition.yml
         > kubectl set image deployment/ myapp deployment nginx =nginx:1.9.1
status   > kubectl rollout status deployment/ myapp deployment
         > kubectl rollout history deployment/ myapp deployment
rollback > kubectl rollout undo deployment/ myapp deployment

## master node
manage, schedule, plan an monitor nodes

* etcd cluster: A distributed, reliable key-value store for the most critical data of a distributed system (nodes, pods, configs, secrets, accounts, roles, bindings...)
    * https://etcd.io/ Port 2379
    * using kubeadm, etcd is deployed as a pod in the kube-system namespace
    * ./etcdctl put key1 value1, ./etcdctl get key1 commands
    * kubectl exec -it -n kube-system etcd-docker-desktop -- sh (inside the pod)
* kube-apiserver (amin door to the k8s server)
    * kubectl -n kube-system get pod kube-apiserver-docker-desktop -o yaml (read the API server manifest)
    * spec:
        containers:
        - command:
            - kube-apiserver
            - --advertise-address=192.168.65.3
            - --allow-privileged=true
            - --authorization-mode=Node,RBAC
            - --client-ca-file=/run/config/pki/ca.crt
            - --enable-admission-plugins=NodeRestriction
            - --enable-bootstrap-token-auth=true
            - --etcd-cafile=/run/config/pki/etcd/ca.crt
            - --etcd-certfile=/run/config/pki/apiserver-etcd-client.crt
            - --etcd-keyfile=/run/config/pki/apiserver-etcd-client.key
            - --etcd-servers=https://127.0.0.1:2379
            - ...
* controller-manager: supervise other components
    * node-controller
    * replication-controller
    * deployment-controller
    * ...
    * kubectl -n kube-system get pod kube-controller-manager-docker-desktop -o yaml
    * spec:
        containers:
        - command:

            - --authorization-kubeconfig=/etc/kubernetes/controller-manager.conf

## worker nodes
host applications as containers

* kubelet: captain on the ship
* kube-proxy
    * a network service is a virtual component to allow access to pods
    * kubectl -n kube-system get pod kube-proxy-b6qdk -o yaml
    * spec:
        containers:
        - command:
            - /usr/local/bin/kube-proxy
            - --config=/var/lib/kube-proxy/config.conf
            - --hostname-override=$(NODE_NAME)
* pod: single instance of an app - 1 pod - 1o* container
    * `kubectl run nginx --image nginx` #Create a new pod using the nginx image
    * kubectl get pods
    * kubectl describe pod nginx
    * kubectl create/replace/apply -f pod-definition.yml
        * in the case of ReplicaSets, new definitions are applied to the new pods. so changes are not applied till old pods deleted
    * kubectl create/apply -f pod-definition.yml
        ```yaml
        apiVersion: v1 | apps/v1
        kind: Pod (v1) | ReplicationController | ReplicaSet | Service (v1) | Deployment (apps/v1) | Namespace (v1)
        metadata (dictionary): name | labels
        spec: containers (list)
        ```
    * kubectl delete pod webapp
* ReplicaSet is a ReplicationController with the tag `selector: matchLabels` to include pods out of the ReplicaSet definition
  * `kubectl get rs -n default`
  * kubectl scale --replicas=6 -f myfile.yaml
  * kubectl scale --replicas=6 replicaset my-replicaset
  * kubectl describe replicaset new-replica-set
* deployment: used for rolling updates to deploy replicasets
    * `kubectl -n hub-stg get deploy`
    * kubectl -n hub-stg get all
    * kubectl -n hub-stg describe deployment hub-stg-helpdesk-helpdesk
    * kubectl -n hub-stg set image deployment/hub-stg-helpdesk-helpdesk helpdesk=docker.sequel.com/hub/helpdesk:1.0.26012-alpha.1
* service:
    * `kubectl get svc`
    * Endpoints field!!
    * NodePort: external access. Range 30.000-32767
        * spec:
            type: NodePort
            ports:
              - targetPort: 80
                port: 80
                nodePort: 30008 
            selector: 
              app: myapp
              type: front-end
    * ClusterIP        
        * spec:
            type: ClusterIP
            ports:
              - targetPort: 80
                port: 80
            selector: 
              app: myapp
              type: back-end
    * Load Balancer    
        * spec:
            type: LoadBalancer
            ports:
              - targetPort: 80
                port: 80
                nodePort: 30008 
            selector: 
              app: myapp
              type: front-end
* namespace:
  * default
  * kube-system
  * kube-public
  ```yaml
  apiVersion: v1
  kind: Namespace
  metadata:
    name: dev
  ```
  * `kubens dev` | `kubectl config set-context $(kubectl config current-context) --namespace=dev`
  * `kubectl get pods --all-namespaces` | `kubectl get pods -A`
  * `kubectl get ns`
  * dns db-service.dev.svc.cluster.local | service-name.namespace.svc.domain
* ResourceQuota (v1)
  ```yaml
  metadata:
    name: ns-quota
    namespace: dev
  spec:
    hard:
      pods: "10"
      requests.cpu: "4"
      request.memory: 5Gi
      limits.cpu: "10"
      limits.memory: 10Gi
  ```

## Tips
```shell
#Generate POD Manifest YAML file (-o yaml). Don't create it(--dry-run)
kubectl run nginx --image=nginx --dry-run=client -o yaml 

#Generate Deployment YAML file (-o yaml). Don’t create it(–dry-run) and save it to a file.
kubectl create deployment --image=nginx nginx --dry-run=client -o yaml > nginx-deployment.yaml

#Make necessary changes to the file (for example, adding more replicas) and then create the deployment.
kubectl create -f nginx-deployment.yaml

#In k8s v1.19+, we can specify the --replicas option to create a deployment with 4 replicas.
kubectl create deployment --image=nginx nginx --replicas=4 --dry-run=client -o yaml > nginx-deployment.yaml
kubectl create deployment httpd-frontend --replicas=3 --image=httpd:2.4-alpine
```
